本文档结合你的论文《基于单片机的智能台灯设计》和当前工程实现，整理了答辩中老师可能重点提问的问题，并给出适合现场回答的参考答案。

- 答辩时不要机械背诵

## 1. 课题整体相关问题

### 1.1 你这个课题主要解决什么问题？

**参考回答：**

本课题主要解决传统台灯亮度固定、依赖人工操作以及离开后容易忘记关灯的问题。系统通过环境光检测实现自动调光，通过人体红外检测实现延时关灯，同时保留按键和编码器的人机交互功能，使台灯既能自动工作，也能手动调节，从而提升照明舒适性和节能效果。

### 1.2 你的系统主要实现了哪些功能？

**参考回答：**

本系统主要实现了五项功能：

1. 环境光照度采集
2. 自动模式下的调光控制
3. 手动模式下的编码器调光
4. 人体检测与无人延时关灯
5. OLED 实时显示工作状态

这五部分共同构成了一个完整的桌面智能照明系统。

### 1.3 这个课题的工程意义在哪里？

**参考回答：**

这个课题的工程意义主要在于，它把光照传感、人体检测、PWM 调光和本地交互集成在一个小型嵌入式系统中，形成了一套完整的智能台灯实现方案。虽然功能本身不算特别复杂，但它具备明确的系统结构和完整的软硬件联动逻辑，对小型智能照明设备设计具有参考价值。

## 2. 主控与硬件选型问题

### 2.1 为什么选 STM32F103C8T6 作为主控？

**参考回答：**

选择 STM32F103C8T6 的原因主要有三点。

第一，它的性能和资源比较适合本课题。主频 72MHz，具备 I2C、定时器 PWM、中断、GPIO 等外设资源，能够同时处理光照采集、编码器输入、OLED 刷新和 PWM 调光。

第二，它的开发生态比较成熟。STM32CubeMX 和 HAL 库能简化底层初始化，降低开发难度。

第三，它成本较低，资料丰富，适合毕业设计这种完整系统实现类课题。

### 2.2 为什么不用 51 单片机？

**参考回答：**

51 单片机也能实现部分功能，但本课题涉及的模块较多，包括 I2C 通信、OLED 显示、编码器输入、人体检测、自动调光和多周期任务调度。相比之下，51 单片机算力和外设资源更有限，软件组织复杂度会更高，扩展性也较差，因此 STM32 更适合本课题。

### 2.3 为什么不用 ESP32？

**参考回答：**

ESP32 的优势主要在于 Wi-Fi 和蓝牙，适合联网控制和物联网应用。但本课题当前重点是本地环境感知、自动调光和人机交互，没有涉及远程控制和云端通信，因此使用 STM32 可以让系统结构更简洁，也更符合本课题的实现目标。

## 3. BH1750 相关问题

### 3.1 BH1750 的工作原理是什么？

**参考回答：**

BH1750 是一种数字式环境光照传感器。它内部包含光敏阵列、放大电路和模数转换电路，可以把光信号直接转换成数字量输出。相比模拟光敏器件，它不需要额外设计复杂的放大和 ADC 采样电路，因此更适合嵌入式系统直接使用。

### 3.2 为什么选择 BH1750？

**参考回答：**

选择 BH1750 主要因为它有三个优点。

第一，输出的是数字量，接口简单，直接通过 I2C 读取照度数据。

第二，精度和稳定性较好，输出值接近实际 lux 值，便于后续自动调光判断。

第三，它体积小、成本低、资料多，适合本课题这种桌面级智能照明系统。

### 3.3 你的 BH1750 是怎么和单片机通信的？

**参考回答：**

本系统使用的是硬件 I2C1 总线通信。引脚为：

- `PB6` 作为 `SCL`
- `PB7` 作为 `SDA`

BH1750 初始化后进入连续高分辨率测量模式，主程序每 200ms 读取一次数据，再把两字节原始值按公式换算成 lux。

### 3.4 你项目里的光照计算公式为什么是 `raw / 1.2`？

**参考回答：**

这是 BH1750 在默认测量参数、连续高分辨率模式下的数据手册推荐换算公式。BH1750 输出的是 16 位原始值，按标准换算关系可以得到近似的 lux 值，所以程序中采用 `lux = raw / 1.2f`。这个公式适用于当前设置的 `0x10` 模式。

### 3.5 为什么还要对光照值做滤波？

**参考回答：**

因为环境光采样容易受到人体遮挡、桌面反光和灯光波动影响，如果直接使用原始值，会导致 OLED 显示跳变明显，自动调光也会频繁波动。为了让照度值更平滑，程序加入了长度为 5 的滑动平均滤波，这样显示和调光判断都会更稳定。

## 4. I2C 原理与工程实现问题

### 4.1 I2C 的基本原理是什么？

**参考回答：**

I2C 是一种同步串行总线通信协议，只需要两根线：

- `SCL`，时钟线
- `SDA`，数据线

通信时由主机产生时钟，从机按时钟节拍在数据线上发送或接收数据。每个从设备都有自己的地址，主机通过地址来选择与哪个设备通信。

### 4.2 I2C 为什么只需要两根线就能挂多个设备？

**参考回答：**

因为 I2C 是总线结构，多个从设备共用同一组 `SCL` 和 `SDA`。主机在开始通信时先发送目标地址，只有地址匹配的设备才会应答，其他设备保持不响应。所以即使多个设备挂在同一总线上，也不会混淆。

### 4.3 你这个项目里 I2C 总线上挂了哪些设备？

**参考回答：**

当前项目的 I2C1 总线上挂了两个设备：

- `BH1750`
- `SSD1306` OLED

它们共用 `PB6/PB7` 两根线，通过不同 I2C 地址区分。

### 4.4 为什么 I2C 的引脚要配置成开漏输出？

**参考回答：**

I2C 总线要求设备只能主动拉低总线，而高电平由上拉电阻提供，因此引脚通常配置为开漏输出。这样多个设备可以安全共用同一总线，不会因为两个设备同时驱动高低电平而产生冲突。

### 4.5 你使用的是模拟 I2C 还是硬件 I2C？

**参考回答：**

当前工程使用的是硬件 I2C，也就是 `I2C1` 外设，不是软件模拟 I2C。代码中由 `MX_I2C1_Init()` 完成初始化，`BH1750` 和 `OLED` 都通过 `HAL_I2C_Master_Transmit()` 和 `HAL_I2C_Master_Receive()` 与单片机通信。

### 4.6 为什么 I2C 速度设置为 100kHz？

**参考回答：**

因为本项目的数据量不大，100kHz 标准模式已经足够满足 BH1750 采样和 OLED 刷新需求。使用标准模式有利于提高通信稳定性，也符合这类低速外设的常规应用场景。

## 5. HC-SR501 与人体检测相关问题

### 5.1 HC-SR501 的工作原理是什么？

**参考回答：**

HC-SR501 是基于热释电红外原理的人体检测模块。人体会向外辐射红外线，传感器通过检测红外辐射变化来判断是否有运动人体进入检测区域。它更准确地说是“人体运动检测”，而不是“绝对静态存在检测”。

### 5.2 为什么 HC-SR501 对静止人体识别不够好？

**参考回答：**

因为热释电红外传感器本质上检测的是红外辐射变化，而不是持续的绝对红外强度。人体如果长时间静止，辐射变化减小，模块就可能判断为无人。这也是 PIR 方案的典型局限。

### 5.3 你是如何缓解 PIR 误关灯问题的？

**参考回答：**

本系统采用了硬件延时和软件延时结合的方式。硬件方面，HC-SR501 模块本身可通过电位器设置输出保持时间；软件方面，主程序每 100ms 检测一次人体状态，并设置 60 秒无人计时阈值。这样可以避免因为瞬时离开或短暂静止而立刻关灯。

### 5.4 为什么你项目里 PB13 配成下拉输入？

**参考回答：**

因为 HC-SR501 的输出是一个数字高低电平。如果模块未供电或者暂时未驱动输出，引脚可能悬空。将 `PB13` 配成下拉输入，可以让未驱动时默认保持低电平，减少误判。

### 5.5 为什么有时候离开后不是正好 60 秒关灯？

**参考回答：**

程序里的软件计时确实是 60 秒，但 HC-SR501 模块本身带有输出保持延时，也就是人离开后它的输出不会立刻变为低电平，而会再保持一段时间。因此实际从离开到关灯的总时间通常是“模块硬件延时 + 软件 60 秒计时”的叠加结果。

## 6. 编码器与按键相关问题

### 6.1 独立按键为什么不用外部中断，而用轮询？

**参考回答：**

按键操作频率低，而且机械按键存在抖动问题。用固定周期轮询更容易同时完成消抖和长短按识别。对本课题来说，10ms 轮询已经足够满足实时性需求，也比中断处理更简单稳定。

### 6.2 你的按键具体实现了什么功能？

**参考回答：**

按键实现了两种操作：

- 短按：开灯或关灯
- 长按：切换自动模式和手动模式

程序通过按下持续时间来区分短按和长按。

### 6.3 EC11 编码器的工作原理是什么？

**参考回答：**

EC11 是一种机械式增量编码器，通常有 A 相和 B 相两个输出，相位相差 90 度。旋转时 A/B 相会产生交替变化的脉冲，通过判断相位先后关系，就可以知道旋转方向；通过计数脉冲变化，就可以得到旋转步进。

### 6.4 你的编码器是怎么实现的？

**参考回答：**

当前工程中，编码器采用的是“底层中断采样，上层轮询取结果”的方案。

- `PA0` 作为 A 相，配置为 EXTI 双边沿中断
- `PA1` 作为 B 相，辅助判向
- A 相每次翻转时进入中断，在中断中读取 A/B 两相信号判断方向
- 中断只累计步进结果
- 主循环每 10ms 调用 `EC11_Process_10ms()` 取出 `-1/0/+1`

这样既保证了响应及时性，也避免把业务逻辑全部写进中断中。

### 6.5 相比纯轮询，这种编码器方案有什么优点？

**参考回答：**

相比纯轮询，当前方案的优点是边沿一到就能被中断捕获，更不容易在快速旋转时漏步，响应也更及时。

### 6.6 相比“中断里直接调亮度”，你现在的方案有什么优点？

**参考回答：**

当前方案把中断控制在很轻的级别，中断里只做采样和记步进，不直接改亮度和模式。这样可以避免中断逻辑过重，提高系统稳定性，同时也让主要业务逻辑仍然集中在 `main.c` 中，更便于维护和调试。

## 7. PWM 与 LED 调光相关问题

### 7.1 PWM 调光的原理是什么？

**参考回答：**

PWM 调光是通过改变周期内高电平所占比例，也就是占空比，来改变 LED 的平均功率。占空比越高，LED 平均亮度越高；占空比越低，平均亮度越低。由于 PWM 开关速度很快，人眼看到的是平均效果，因此可以实现亮度调节。

### 7.2 为什么不用直接调电压，而用 PWM 调光？

**参考回答：**

因为 PWM 调光效率更高、发热更小，也更适合 LED 控制。直接调压不仅效率低，而且在不同工作点下 LED 的亮度和电流关系不够稳定。对于单片机系统来说，利用定时器输出 PWM 是更成熟、更简单的方案。

### 7.3 你项目里的 PWM 是怎么实现的？

**参考回答：**

本项目使用 `TIM1_CH1` 输出 PWM，实际引脚是 `PA8`。定时器设置为：

- `Prescaler = 7`
- `Period = 999`

所以 PWM 频率约为 `72MHz / 8 / 1000 = 9kHz`。主程序通过更新比较寄存器值来改变占空比，从而实现 LED 亮度控制。

### 7.4 为什么 PWM 频率选 9kHz？

**参考回答：**

因为较高的 PWM 频率有助于减小肉眼可感知的闪烁。9kHz 已经远高于人眼直接感知频闪的范围，既能保证调光效果，也适合当前 LED 驱动方式。

### 7.5 为什么亮度等级是 0 到 199，而 PWM 占空比是 0 到 1000？

**参考回答：**

因为系统把“用户可理解的亮度等级”和“底层实际 PWM 输出”分开处理。`0~199` 表示逻辑上的亮度级数，便于手动调节和自动调节；而 `0~1000` 是底层 PWM 比较值范围，便于与定时器周期对应。中间通过 Gamma 表把亮度级数映射到 PWM 占空比。

## 8. 调光算法相关问题

### 8.1 你的自动调光算法是怎样的？

**参考回答：**

系统先读取经过滤波的环境照度值，然后在自动模式下进行分段判断：

- 低于 `500 lx` 时提高目标亮度
- 处于 `500~530 lx` 时保持不变
- 高于 `530 lx` 时降低目标亮度

这是一种基于目标照度和死区范围的简单闭环控制方法。

### 8.2 为什么要设置死区？

**参考回答：**

如果不设置死区，环境照度只要在目标值附近有微小波动，系统就会频繁加亮或减亮，导致亮度不断抖动。设置死区后，在允许范围内保持当前亮度不变，可以减少频繁调节，提高稳定性。

### 8.3 你的死区是对称的还是非对称的？

**参考回答：**

当前实际程序采用的是非对称、也就是单边死区控制，不是传统的 `±30 lx` 对称死区。具体逻辑是：

- `<500 lx` 增亮
- `500~530 lx` 保持
- `>530 lx` 降亮

### 8.4 什么是 Gamma 映射？为什么要引入它？

**参考回答：**

Gamma 映射是把逻辑亮度等级按照非线性关系映射为 PWM 输出值。因为人眼对亮度变化的感知不是线性的，尤其在低亮度区域更敏感。如果直接线性调光，低亮度变化会显得不均匀。引入 Gamma 映射后，调光会更符合视觉感知。

### 8.5 什么是渐变调光？为什么要做这个？

**参考回答：**

渐变调光就是不让 PWM 输出立刻跳到目标值，而是让当前亮度每次只变化一个小步进，逐步逼近目标亮度。这样可以避免灯光突然变亮或突然熄灭，提高视觉舒适性。

### 8.6 你的系统里“目标亮度”和“当前亮度”为什么要分开？

**参考回答：**

分开处理是为了实现渐变调光。

- `Target_Brightness` 表示系统想达到的亮度等级
- `Current_PWM` 表示当前实际输出等级

主程序让 `Current_PWM` 每 10ms 向 `Target_Brightness` 靠近，而不是一步跳过去，这样亮度变化就会更平滑。

## 9. OLED 显示相关问题

### 9.1 你为什么选 OLED，而不是 LCD1602？

**参考回答：**

OLED 的优点是体积小、对比度高、可视角度大，而且支持 I2C 接口，占用引脚少。相比 LCD1602，它更适合显示中文标签、照度数值和状态信息，也更符合本课题的界面需求。

### 9.2 OLED 为什么会闪烁？你是怎么优化的？

**参考回答：**

如果每次刷新时都整屏清空再重画，就会造成明显闪烁。为减少闪烁，本项目采用了两种优化：

第一，静态标签只在初始化时绘制一次；  
第二，动态数据区只在数值变化时局部刷新。

这样可以显著减少 I2C 通信量和屏幕重绘次数，提高显示稳定性。

### 9.3 你 OLED 显示了哪些内容？

**参考回答：**

OLED 当前显示四行内容：

- 模式：自动或手动
- 当前照度：xx lux
- 调光级数：xxx
- 人体状态：有或无

这些内容基本覆盖了系统运行状态和用户最关心的信息。

## 10. 软件结构与程序设计相关问题

### 10.1 你的程序为什么不用 RTOS？

**参考回答：**

因为当前任务数量不多，逻辑关系比较清晰，实时性要求也没有复杂到必须引入 RTOS。使用基于 `HAL_GetTick()` 的多周期任务调度可以更简单地实现各模块协同运行，同时更便于理解和调试。

### 10.2 你的程序为什么分成 10ms、100ms、200ms、500ms 四类任务？

**参考回答：**

因为不同功能对实时性要求不同。

- 按键、编码器和渐变调光需要响应更快，所以放在 10ms 任务
- 人体检测不需要特别高频，100ms 足够
- 光照采样和自动调光也不需要太快，200ms 比较合适
- OLED 刷新如果太快反而容易闪，所以放在 500ms 任务

这种分层调度方式能兼顾响应速度和系统稳定性。

### 10.3 你的程序中最核心的状态变量有哪些？

**参考回答：**

最核心的状态变量包括：

- `Power_State`
- `Auto_Mode`
- `Target_Brightness`
- `Current_PWM`
- `Ambient_Lux`
- `PIR_Count`

它们共同描述了系统当前的开关状态、模式状态、调光目标、实际输出和人体检测状态。

### 10.4 你的代码为什么要模块化？

**参考回答：**

模块化的好处是职责清晰。比如：

- `bh1750.c` 只负责光照采集
- `hcsr501.c` 只负责人体检测
- `key.c` 和 `ec11.c` 只负责输入
- `pwm_ctrl.c` 只负责输出
- `oled.c` 只负责显示

这样主程序 `main.c` 只需要负责调度和逻辑决策，代码结构更清晰，也更方便调试和维护。

## 11. 测试与结果相关问题

### 11.1 你是如何验证自动调光功能有效的？

**参考回答：**

我通过改变环境初始照度，观察系统在自动模式下的调光级数和最终照度变化。测试结果表明，在较暗、中等和较亮环境下，系统都能把照度调整到接近 `500~530 lx` 的目标范围，因此说明自动调光功能是有效的。

### 11.2 为什么在亮环境下 LED 会降到 0 级？

**参考回答：**

因为当环境照度已经高于目标照度上限时，系统判断外部光已经足够，不需要 LED 再补光。此时自动调光会持续降低目标亮度，最终 LED 可以降到最小甚至关闭，以避免无效照明。

### 11.3 你的系统测试中有哪些局限？

**参考回答：**

当前测试的局限主要有两点。

第一，人体检测受 HC-SR501 本身原理限制，对静止人体识别不够理想。  
第二，光照测试中使用手机照度计软件作为参考，这种方式更适合验证变化趋势和基本有效性，不等同于专业照度计的高精度标定。

## 12. 不足与展望相关问题

### 12.1 你认为系统当前最大的不足是什么？

**参考回答：**

我认为最大的不足有两个：

第一，PIR 方案对静止人体识别有限，可能在特殊情况下出现误关灯。  
第二，自动调光算法目前还是比较简单的分段控制，没有使用更精细的闭环算法，因此在复杂环境变化下还有优化空间。

### 12.2 如果继续做，你准备怎么改进？

**参考回答：**

后续可以从三个方向改进：

1. 引入距离传感器或其他辅助感知，提高静止人体识别能力
2. 引入 PID 或自适应控制算法，提高调光精度和稳定性
3. 扩展无线联网功能，实现 APP 控制或接入智能家居平台

### 12.3 你的项目创新点在哪里？

**参考回答：**

本课题的创新点主要不是某个单一理论算法，而是面向实际应用完成了一套完整的小型智能照明系统集成方案。系统综合使用了环境光检测、人体检测、本地交互、滑动平均滤波、死区判断、Gamma 映射和渐变调光等方法，使其在结构简洁的前提下，能够较稳定地实现智能调光和节能控制。

## 13. 现场答辩时的回答技巧

### 13.1 遇到原理问题怎么答

建议结构：

1. 先讲基本原理
2. 再讲为什么适合本课题
3. 最后讲当前工程里怎么实现

例如 I2C、PWM、PIR、Gamma 映射都适合这种回答方式。

### 13.2 遇到“为什么这样设计”怎么答

建议结构：

1. 先说备选方案
2. 再说它们的问题
3. 最后说明当前方案为什么更合适

例如：

- 为什么不用 51
- 为什么不用中断按键
- 为什么编码器采用中断采样加轮询取值

### 13.3 遇到不会的问题怎么答

可以回答：

“这个问题我目前的理解是……”

或者：

“当前项目里我主要是这样实现的，从工程角度看……”

不要直接说“不会”，尽量把问题往你已经实现的代码和测试结果上引。
